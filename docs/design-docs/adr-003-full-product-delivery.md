# ADR-003：全功能实现与质量验收分开推进

日期：2026-10-30。状态：接受。依据：用户本日明确要求先落地全部规划功能、架构师参与重排；Astra/low task_architect已只读评估总方案、现有设计和功能清单，结论由主控持久化。

## 改变的决定

取消“F006人评未通过就不开发后续模块”的全局开发门禁。保留总方案51项功能、现有四层Python核心、原始素材/模型证据/费用身份和旧人工记录。F006/F009/F010未通过的事实不变；它们只限制相关质量声明和商用发布资格。商业目标是全部功能真正可用，而非展示页面或假服务。

本决定覆盖当前phase-0-plan、Phase 0规格与开发三角色流程中关于后续开发必须等待质量门槛的旧规定；原总方案作为历史来源不改写。总方案§39原将自动发布放在后续，本次全功能目标明确把它列入后段交付，不挤入第一切片。

## 架构

- 继续Domain→Application→Infrastructure/CLI/UI的依赖边界，不重写C#核心、不拆微服务。UI/CLI调用同一Application用例。
- 新链路：Brief→CreativePlan→Script→EditDecision→RenderJob→PublishingPackage，每步保存版本、父版本、来源和完成产物。分析时间线是证据，编辑时间线是创作决策；修改后者不得更改前者。
- 源区间复用整数微秒、media/run/event身份与SHA；输出使用帧号、有理数帧率，显式映射。检索按排名，旧片段篮按源时间，新EDL按创作顺序，三者分开。
- 首切片复用独占新版本目录与最后完成回执，不改旧分析库；正式编辑器以SQLite事务登记项目、修订、任务、产物，媒体仍在文件系统。任务复用原锁/取消/恢复机制，不重发已计费请求。
- 桌面终态为薄Windows EXE宿主＋WebView2＋打包Python核心，复用页面。具体SDK/打包/签名需实证；启动浏览器不算EXE交付。
- 模型、配音、平台发布、支付和授权各有适配边界；离线模板明确标记模板，未联调服务保持部分完成，不能用模拟器或客户端开关冒充商用服务。

## 三类状态

1. 实现：有真实入口，正常/失败路径有效，保存后另进程可回读，有实际结果。JSON规划不算MP4；模板名字不算模式端到端完成。
2. 质量：真实人评、事实/字幕/配音/结构与各内容模式效果。原U10每主查询≥70%不降低，缺少人评继续未知。
3. 商用发布：安装/升级/卸载、凭据保护、组件及素材来源、账号/支付联调、恢复和权限均有实证。TD003限制对应二进制分发，不阻断使用已有固定工具的本地渲染开发。

未完成项继续占总分母。对外发布、真实账号操作、新付费调用仍按具体授权执行；用户此次加速开发指令不自动批准这些外部动作。
