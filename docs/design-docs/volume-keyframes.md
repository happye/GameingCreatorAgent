# 原声音量关键帧（阶段C，2026-11-11）

用户 J1 第五次反馈第3条：要像 PR/AE 那样看到波形、在时间上打音量节点，但保持轻量。

## 决定

- **数据**：`AudioMix` 增加可选 `sourceEnvelope`：按成片帧号严格递增的点 `{frame, gainDb}`，最多 64 个，gainDb ∈ [-60, 0]。它叠加在已有的 `sourceGainDb` 上。点之间按 dB 线性插值，第一个点之前、最后一个点之后保持端点值。
- **兼容**：信封为空时 JSON 里不出现这个键。旧版本、旧请求哈希和旧回执完全不变，不需要迁移。
- **成片**：FFmpeg 在原声链上 `volume=原声增益dB` 之后，再接一个 `volume='pow(10,(分段表达式)/20)':eval=frame`。表达式用 `t`（成片时间）写成嵌套的 `if(lt(t,…))`。闪避仍用未衰减的原声做侧链，与现在的规则一致。
- **试听**：每次渲染按播放头位置算出“原声增益＋信封值”，交给现有的 AudioPreviewGraph，不新增节点。
- **界面**：在波形道上画一条音量线：点空白处加点，拖动点改时间和音量，双击点删除；一次拖动算一步撤销。保存版本时随 audioMix 一起提交。
- **不做**：配乐和旁白的信封（以后同一结构可复用）、贝塞尔曲线、专业时间线导出（FCPXML/OTIO/Premiere XML 不带信封，导出提示照旧写“增益需在剪辑软件中复核”）。

## 验收

- 域：校验、插值、表达式单元测试。
- 成片：用生成的恒定音调渲染，测信封前后两段的电平差约等于设定的 dB。
- 浏览器：加点、拖动、撤销、保存后重新打开，信封仍在。
