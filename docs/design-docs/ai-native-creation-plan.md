# AI 主导的创作闭环：重构方案（2026-11-11，J1 第五次试用后）

起因：J1 第五次试用（2026-11-11）结论仍是“发不出去”。本方案回答两件事：AI 现在到底在哪里；怎样做才能让这个工具真正可用。界面结构沿用 [创作工作台重构方案](创作工作台重构方案.md)，本方案只改“谁来做判断”和闭环。

## 一、实话：现在 AI 在哪里，不在哪里

| 环节 | 现在是谁在做 | 结果 |
| --- | --- | --- |
| 看懂素材（片段摘要、动作、细节） | **AI**：DeepSeek 视觉模型，每条录像付费分析一次 | 摘要能用，但只描述“画面上有什么” |
| 语音转文字、语义搜索 | **本机模型**：faster-whisper、e5 向量 | 能搜到画面，但不懂“玩法思路”这类编辑概念 |
| 理解需求（一句话） | **规则**（正则） | 你的那句话被拆错：“技能解说”被当成类型，主题只识别出第一个 |
| 选片、排方案、剪辑决策 | **模板**（来源顺序/倒序/开场高光…） | 4 个方案只是同一批片段的不同排列 |
| “必须主题”检查 | **字符串匹配**（主题词必须出现在画面摘要里） | “可玩角色介绍”永远匹配不上 → 方案全灰 |
| 旁白稿、标题、简介 | **模板拼接**画面摘要 | 简介是摘要堆砌，标题是你的需求原文 |
| 动态策划（文字 AI） | **AI**：DeepSeek 文本模型，但**每次调用都要你单独批准** | 只真正跑过 2 次，没进入日常流程 |
| 配音 | 本机免费 Windows 声音；云端 CosyVoice 已接好但需批准 | 音质差 |

所以你的判断是对的：**素材理解用了 AI，创作本身（理解需求、选片、剪辑、文案）几乎全是写死的规则**。原因有两个，都要说清：
1. **费用规则把 AI 挡在了主流程外**：每月 ¥50 只授权“素材分析”，其它“每次新的文字 AI 调用都需单独授权”。开发时为了不违规，Codex 和我都把创作环节做成了不调用 AI 的规则版，AI 只做成一个“准备→等你批准→发送一次”的旁路。
2. **我们按“功能清单打勾”推进，而不是按“成片能不能发”推进**。51 项里每项都“部分可用”，但没有一项是 AI 真正在做判断。这是方向性错误，责任在开发侧。

（顺带澄清：我上次说的“3 套 AI 动态方案”在 11-09 那次已采用的方案任务里（4c857005），不是你这次新生成的 4 个方案——那 4 个都是模板。这个指代没讲清楚，是我的问题。）

## 二、目标：AI 编排、工具执行、人做取舍

一个好的创作工具应该是：你说“给新玩家做 1 分钟 3V3 和 1V1 玩法展示，讲角色、技能、思路、特色”，AI 去素材里找对应画面、排出有起承转合的剪辑、写出像人写的旁白和发布文案；你只在三个点上做决定：**选哪个方案、哪里要改、能不能发**。

```
你：一句话需求 ──► AI 编导（文本大模型，工具调用）
                    ├─ 工具：搜素材（向量+摘要+语音字幕）、看关键帧（视觉模型）
                    ├─ 工具：时间线操作（加/删/裁/排/变速/转场/字幕/音量）
                    ├─ 工具：渲染、出封面候选、算节拍和响度
                    └─ 产出：分镜脚本（每段为什么选、对应哪个主题）+ 时间线 + 旁白 + 标题简介
你：审方案 → 口头/拖拽修改（AI 执行）→ 预览 → 发布前确认
```

原则：
- **需要判断的交给 AI**：理解需求、把“角色介绍/技能解说/玩法思路”映射到具体画面、决定节奏与顺序、写旁白和文案、挑封面。
- **需要确定性的交给工具**：裁剪、渲染、时钟、文件、费用账本——现有工程保护（源时钟、收据、费用门）继续有效。
- **需要人的地方只留取舍**：不再让人手填 10 个字段、手动找关键词、手动凑片段。
- **主题是“内容目标”不是“过滤条件”**：AI 判断哪些片段能讲某个主题；缺素材时说明“能讲但画面弱”，给替代方案，不再把方案整体置灰。

## 三、按你的 8 条反馈落到具体改动

| # | 问题 | 改法 | 需不需要 AI |
| --- | --- | --- | --- |
| 1 | 片段篮里片段互相重叠 | 入篮时按“同一录像”合并重叠/相接区间（显示为一段，可拆开）；选段默认吸附到不重叠的边界；方案生成前再做一次区间并集 | 否（立即可做） |
| 2 | 一句话需求识别错、主题缺失、方案全灰 | 需求理解改由文本模型输出结构化需求（含主题清单）；主题改为软目标，由 AI 给每个主题配片段和覆盖度；方案不再因主题缺口置灰 | **是** |
| 2 | 没有拖拽裁剪 | 时间线片段左右边缘可拖拽（吸附到帧/拍点），可缩放时间轴 | 否 |
| 3 | 声音太差、没有音轨编辑 | 音轨显示波形（FFmpeg 算峰值）；音量包络可加关键帧拖拽，导出时按包络混音；配音建议换云端音色（需你批准费用） | 波形/包络否；配音需付费 |
| 4 | 没有工程概念 | 进入剪辑即建“工程”：有名字；方案、版本、操作记录、参数、成片、发布包都挂在工程下；列表按工程名而不是时间戳 | 否 |
| 5 | 发布页不合格 | 标题/简介/标签由 AI 按平台风格写（简介含作者的话、引流位、可自定模板）；封面在发布信息里先选：AI 给 3–6 个候选帧 + 可手动拖选，任何时候都能改；去掉没用的复制按钮 | **是**（文案、封面打分） |

| 7 | AI 参与度 | 见第一、二节：AI 进入主流程 | **是** |
| 8 | 闭环 | 见第四节分阶段 | — |

## 四、分阶段实施（每阶段都以“能不能发”验收，不再按功能打勾）

**阶段 A：修硬伤（1–2 天，无需新授权）**
片段区间合并去重；目标时长跟随片段篮；主题缺口不再置灰；发布页封面前置可选、标题不再复制需求原文；时间线拖拽裁剪；工程命名（先做轻量版：导出时命名，列表显示名称）。
验收：你用同样 8 段片段，出片时长≈去重后的片段总长，发布页一次填完。

**阶段 B：AI 编导核心（3–5 天，需要你批准费用规则，见第五节）**
文本模型 + 工具调用：需求理解 → 按主题检索与配片 → 分镜脚本与时间线 → 旁白 → 标题/简介/标签；每一步可预览、可撤销；AI 修改（“第二段太长”“加一段技能特写”）走同一工具接口。视觉模型只用于少量关键帧：选封面、复核“这段能不能讲这个主题”。
验收：你那句话 → 3 个真正不同思路的方案（说明每段对应的主题），旁白读起来像人写的，简介可直接发。

**阶段 C：专业编辑体验（3–5 天）**
音轨波形 + 音量关键帧；多轨时间线（画面/旁白/配乐/字幕）；完整工程文件（全部操作记录可回放、跨会话不丢）。
验收：不用 PR/AE 也能完成调音量、裁片、对齐的常见操作。

**阶段 D：质量线**
用你的评分校准 AI 选片和文案（J2 前十名评分、J1 成片评分），记录每次 AI 建议被采用/修改的比例，持续改进提示词与工具。

## 五、需要你拍板的事

1. **AI 费用规则**（最关键）：把“每次文字 AI 调用单独批准”改为**月度预算内自动调用**，例如每月 ¥30，单条视频上限 ¥1，超出才问你，所有调用仍进账本、可查。依据本项目实测：一次 2.6 万 token 的策划调用估算 ¥0.01–0.02；一条视频完整走一遍（需求、方案、修改 5–10 次、文案）约 ¥0.1–0.3；视觉模型看 30 张关键帧约 ¥0.15–0.2。
2. **模型选择**：继续用已接入的 DeepSeek（便宜、已有账本和留痕），还是为编导环节接入更强的模型（效果更好、单价高约一个数量级）。建议先 DeepSeek，留出替换接口。
3. **配音**：是否允许云端配音（CosyVoice 已接好）在预算内使用；不允许就保持本机声音，只做功能不保证音质。
4. **顺序**：建议 A → B → C；A 与 B 可并行（A 我来做，B 需要先定 1、2）。

## 六、对旧规则和旧做法的调整建议

- 交付状态改按“端到端成片能否发布”验收，不再以 51 项各自“部分可用”计进度。
- 规则版（正则需求解析、模板方案、模板文案）保留为**离线兜底**，在 AI 不可用或超预算时使用，界面上明确标注“规则版”。
- 付费调用仍保留：预算上限、单条上限、账本不可改、失败不自动重付、输出留痕——这些保护不变，只是不再每次打断你。
