# 防止同一录像重复付费分析（analysis-reuse-guard，2026-10-27第五会话）

所属阶段：Phase 0（总方案§52“同一视频不要重复分析”、§15 Cache；看板A组“缓存”仍🟡，缺口缩小为“窗口级片段缓存”）；保护验收第4步（唯一花钱的一步）。选题：离线候选排名工作流第三名（7.1/10）。属费用边界，评估者为code-quality-guard（opus）。

## 一、对用户来说多了什么

- 新的`analyze`在**创建任何模型连接、ASR、费用账本之前**，先在项目里找“字节完全相同的录像＋相同分析设置”（提示词版本／哈希、模型、价目版本、取帧间隔、窗口、输出上限、ASR语言、流水线哈希与阶段；费用上限、请求数上限、输入帧上限不算）。
  - 已有**完成**任务：停止，退出码2，`analysis.already_completed`，给出任务ID——直接检索即可，不再付第二次钱。
  - 已有**未完成**同设置任务：按任务清单同一套续跑规则（`nextAction`与`continuationBlockers`）区分——可续跑且同一路径：提示`--resume <任务ID>`（`analysis.already_started`）；可续跑但文件换了路径：说明放回原位置再续跑；不能直接续跑（覆盖缺口、素材完整性、待确认费用、旧版已停止、上限不足、费用上限用完）：说明原因并指向工作台任务清单（`analysis.existing_unfinished`），不再误导去`--resume`。
  - `prepare-media`／批量准备免费建出的新任务，在尚无任何模型调用时`--resume`前也检查：同设置的其他任务已完成或已有模型调用就停止（`analysis.duplicate_of_existing`）。
  - 确实需要另起一次付费分析：显式加`--allow-reanalysis`（新任务与续跑都可用，跳过本检查）。换提示词版本或取帧设置属于不同设置，不被拦。检查范围是同一个项目。
- 只读命令`check-analysis-reuse <录像> --project <项目> --config <配置>`：不分析、不花钱，以只读方式打开项目，输出`wouldStop`、同设置任务与同录像其他设置任务，用于批准付费分析提案前核对。

## 二、合同

- 新任务路径和“尚无模型调用的任务首次续跑”两处检查；已有模型调用的续跑、`prepare-media`、`prepare-media-batch`行为不变。
- 读不出的任务行使检查失败，并点名是哪个任务、说明可用`--allow-reanalysis`跳过，宁可不分析也不在状态不明时付费。
- 只读命令使用与`analyze`相同的配置校验，回答与`analyze`一致。
- 只读命令在项目数据库不存在时不创建项目。

## 三、证据
