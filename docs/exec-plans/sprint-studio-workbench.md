## 第 1 步结果

- 前端库：`src/gamingcreator/ui/static/vendor/`（preact 10.24.3 MIT、htm 3.1.1 Apache-2.0）。已对照 npm registry 完整性哈希校验；`vendor.json` 记录 SHA-256 和一处补丁（hooks 的裸导入改为相对路径，因为 CSP `script-src 'self'` 不允许内联 import map）。许可证已纳入 `collect-third-party-notices.py`。
- 页面：`studio.html`、`studio.css`（深色设计令牌，固定外壳，各面板内部滚动）、`studio/main.js`、`studio/api.js`。只使用现有接口：`/api/projects`、`/api/runs`、`/api/inspect`、`/api/creation/jobs`、`/api/media`、`/api/evidence`。
- 交互：
  - 三个工作区标签；剪辑和发布暂时显示占位，并链接到旧创作页。
  - 素材箱和检查器可以隐藏，偏好记在本机。
  - 点时间轴片段会跳转播放，并显示片段描述和采样帧。
  - 快捷键：空格、←/→、J/L。
  - 新请求会中止旧请求，防止串台。
- 保护：`tests/test_studio_shell.py`，覆盖三点：前端库哈希与清单一致，页面没有内联脚本，7 个路由以正确类型返回。

## 第 2 步结果

- 剪辑区（`studio/edit.js`）的布局：
  - 左侧：需求表单。只需填录像、游戏、类型、秒数、平台；其余收在“高级选项”。草稿按项目保存在本机。
  - 左侧下方：方案卡。每张卡显示时长、镜头数、平均镜头长度和前 8 个镜头的缩略图；推荐模板有标记，有缺口的方案不能选。
  - 中间：预览窗，下面是“方案时间轴”，按成片顺序排列镜头缩略图。
  - 右侧：检查器，显示方案信息、选中镜头的原片位置和描述，以及导出设置。
- 即时预览（`studio/preview.js`）：按方案的剪辑清单在原片里跳着播放，同一来源相邻的片段连续播放、不重新定位，输出时钟独立计算；完全不需要渲染。同时用动画帧和视频的 `timeupdate` 驱动，窗口在后台时也能跨片段。
- 导出：沿用原有接口；同一意图复用同一个 `requestId`；完成后预览窗切到成片，提供下载。刷新后会自动重新打开上次的方案或成片。
- 素材箱“我的作品”里的方案和成片可以点击，会在剪辑区打开。
- 实测（demo-phase0，漫画群星，玩法展示 60 秒）：方案生成 1.9 秒；预览从开场镜头（原片 84 秒处）跳回原片开头并连续推进；导出得到 60.0 秒的 MP4（47.2 MB）；页面没有滚动条。
- 保护：`tests/test_studio_edit_browser.py` 使用真实服务器和真实任务系统（只替换了规划器和渲染器），走完“需求 → 方案 → 有缺口的方案不能选 → 导出 → 可下载 → 刷新后草稿和成片还在”。

## 第 3 步结果

- 编辑（`studio/clipedit.js`）：选方案后读取服务器的可编辑镜头表（`/api/creation/jobs/{id}/edit`）。点时间轴上的一段，检查器里可以：在原片范围内裁短入点/出点、改速度（0.5×/1×/2×，即服务器允许的三种）、设进入方式（直接切换或交叉淡化）、前移/后移、删除（也可按 Delete）。预览窗按改后的镜头表即时播放（速度用 `playbackRate`；转场在预览中显示为直接切换）。
- 版本：“保存版本”提交 `/api/creation/revisions`，带上父任务的回执哈希；“导出成片”有未保存修改时先保存，再从版本渲染。刷新后重新打开上次的版本（带修改），从版本导出的成片也能找回它的版本。
- 一句话修改：底部创作助手调用 `/api/creation/timeline-commands`，先在时间轴上高亮会变化的段并显示前后时长，用户点“应用”才生效；预览期间禁止导出。
- 实测（demo-phase0）：“第2个镜头慢放”高亮 1 段，60.0 → 61.0 秒；保存版本 → 刷新还原 0.5× 标记 → 导出得到 1:01 的 MP4 → 刷新后成片和版本都在。
- 修复：素材无法播放时预览器不再抛出未处理的异常。
- 保护：`tests/test_studio_edit_browser.py::test_edit_clip_save_version_and_command`（真实服务器与版本任务，替换时间线存储和渲染器）：改速度 → 保存版本 → 刷新还原 → 一句话预览只高亮 1 段 → 应用后显示未保存。

## 第 4 步结果（第一部分）

- 声音面板（`studio/audio.js`，检查器里未选中镜头时显示）：
  - 旁白：起草旁白稿（现有离线模板）→ 可编辑文本，显示预计秒数与成片秒数 → 用本机 Windows 语音合成 → 放进成片。可调起点、音量、“旁白响起时压低原声和音乐”。旁白比起点后剩余时长更长时禁止保存，并提示改短文字或提前起点，不截断。
  - 配乐：从本机音乐库选择，或直接上传（≤30 MB，wav/mp3/flac/ogg/m4a/aac；版权为用户声明，不核验，只存本机）；可调配乐音量、原声音量、“游戏声音大时自动压低配乐”。
  - 时间轴下方显示旁白条和配乐条。
- 即时预览：旁白和配乐与方案播放器同步（漂移超过 0.3 秒重新对齐；配乐与渲染一致循环）；原声按所设音量播放。
- 保存与导出：声音设置随版本保存（`audioMix`、`narration`），刷新后还原；导出的成片带旁白，并附旁白文本。
- 新接口：`POST /api/creation/music`（上传登记），`GET /api/creation/music/{trackId}/audio?receipt=`（试听）。
- 实测（demo-phase0）：模板旁白稿 184 字 → 本机语音 49.6 秒；起点设 20 秒时提示“只剩 41.0 秒”并禁止保存；起点 5 秒时预览中旁白与画面同步；保存 → 刷新还原 → 导出 MP4（47.4 MB）。
- 已知不足：模板旁白稿是画面描述的拼接，不像解说；Windows 中文语音只有 Huihui，听感机械。两者都等提供方方案批准后改进。
- 保护：`tests/test_studio_edit_browser.py::test_narration_draft_synthesize_and_save`（假语音引擎）：起草 → 改稿 → 合成 → 旁白条出现 → 保存 → 刷新还原，只合成一次。

## 第 4 步结果（第二部分：云端音色）

- 用户试听后选定 龙安洋（`cosyvoice:longanyang`）为默认音色。
- 声音列表同时给出本机音色和 6 个云端音色。未配置 Key 时，云端音色显示“（未配置）”且不可选。
- 选中云端音色时，显示预计费用和本月已用/上限；按钮为“确认付费合成（约 ¥…）”，请求里带上确认金额。
- 服务器端闸门（`narration_jobs.paid_gate`）：
  - 没有 Key 时拒绝。
  - 确认金额低于估算时拒绝。
  - 同项目、同音色、同文字时复用已有结果。
  - 超过每月 ¥5 时拒绝。
  - 账单记录：`artifacts/billing/narration-tts.jsonl`。
- 资产格式不变（WAV + 文本 + 回执，引擎记为 `cosyvoice-v3-flash`），版本、混音和渲染无需改动。
- 保护：
  - `tests/test_narration_jobs.py::test_cloud_narration_is_confirmed_capped_recorded_and_never_repaid`
  - `tests/test_studio_edit_browser.py::test_cloud_voice_confirms_cost_before_paying`
  - 两者都用假提供方，不联网。

## 第 4 步补充：声音面板可见性（用户反馈）

- 用户找不到声音面板，原因有两个：
  - 面板只在没选中镜头时显示。
  - 重启后已打开的页面没刷新，还在跑旧代码。
- 修正：
  - 检查器改为“镜头 / 声音 / 导出”三个页签。
  - 时间轴下固定显示旁白轨、配乐轨，点击跳到“声音”页。
- 测试改为走用户路径：先选镜头再点“声音”；从空的旁白轨进入。

## 第 5 步结果

- 素材区左栏新增“搜索片段”：
  - 在所有分析完成的录像里，按分析描述、机制标签和不确定说明做本地文字匹配（多个词同时满足），结果带缩略图、录像名和时间。
  - 不写检索记录，不调用模型。
  - 原有的项目检索有质量闸门、常拒答（实测“团战”0 条），不适合挑片。
- 片段篮：
  - 加入方式：搜索结果上的“+”、检查器的“加入片段篮”、快捷键 B。
  - 已加入的片段在时间轴上加绿框。
  - 片段篮按项目存在本机浏览器里，刷新后还在；可移出、清空。
- “用片段篮生成方案”：
  - 点击后切到剪辑区并勾选“只用片段篮里的 N 段”，录像按篮里的片段自动选择。
  - 篮内总时长短于目标秒数时会提示。
- 后端：
  - 方案请求新增可选 `eventIds`（不超过 500 个、不能重复、必须属于所选录像），原样传给规划器。
  - 规划器原本就支持只用指定片段。
- 实测（demo-phase0）：
  - 搜“跳跃”命中 5 段，全部加入；再搜“攻击”，点开一条后按 B 加入，共 6 段、8 秒。
  - 生成 4 个方案，都是 5.0 秒，所有镜头都来自片段篮。
  - 有 2 段没用上：它们来自同一原片的另一次分析（同一媒体、同一时间），规划器按重复画面跳过。
- 顺带修复：
  - 录像列表还没加载时就输入搜索，结果会一直为空。
  - “+”按钮没有可读名称。
  - 素材区点击无法播放的视频时报未处理异常。
- 保护：
  - `tests/test_creation_jobs.py::test_plan_from_clip_basket_passes_only_those_events`
  - `tests/test_studio_edit_browser.py::test_clip_basket_search_add_and_plan_uses_only_basket`：搜索 → “+” → 打开另一条 → B → 用片段篮生成 → 规划器只收到这两段 → 刷新后片段篮还在。
- 未做：从剪辑区把方案中的某个镜头换成篮内片段（替换镜头），留到下一步。

## 第 6 步结果（发布区）

- 发布区（`studio/publish.js`）取代原来的占位页：
  - 左栏：成片列表。
  - 中间：成片播放器，“用当前画面做封面”记录帧号。
  - 右栏：标题、简介、标签（按需求自动起草的模板，显示字数和标签数），“保存发布信息”。
- 保存后：
  - 生成发布版本并截取封面，封面显示在右栏。
  - 中间下方可选平台（B站、抖音、快手、小红书的本地预设），点“生成平台包”：转码、打包，显示本地检查结果，可下载 zip 或单独的视频。
  - 不会发布到任何平台；真实发布需要用户另行批准。
- 素材箱“我的作品”里的“封面与文案”“平台预览包”现在可以点开，打开到发布区。
- 实测（demo-phase0）：
  - 最新成片（61 秒）自动带出草稿；标题改为“漫画群星：三分钟看懂大乱斗玩法”，封面取第 300 帧（10 秒），保存后封面宽 1280。
  - 生成 B站包：本地检查通过；因为配乐是“仅测试”的音调，显示“发布受阻”。
  - zip 可下载（27.9 MB）；从“我的作品”重新打开，标题、封面帧和包都还在。
- 保护：`tests/test_studio_publish_browser.py`。真实静态服务器加模拟接口：草稿带出 → 未保存时不能打包 → 改标题保存（请求带回执哈希、标签）→ 生成平台包 → 下载链接正确。
- 旧页面（`/`、`/creation`）和它们的模拟测试暂时保留。等用户在新工作台走完一次 J1，再按原计划删除。
