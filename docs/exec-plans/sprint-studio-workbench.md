## 第 1 步结果

- 前端库：`src/gamingcreator/ui/static/vendor/`（preact 10.24.3 MIT、htm 3.1.1 Apache-2.0）。已对照 npm registry 完整性哈希校验；`vendor.json` 记录 SHA-256 和一处补丁（hooks 的裸导入改为相对路径，因为 CSP `script-src 'self'` 不允许内联 import map）。许可证已纳入 `collect-third-party-notices.py`。
- 页面：`studio.html`、`studio.css`（深色设计令牌，固定外壳，各面板内部滚动）、`studio/main.js`、`studio/api.js`。只使用现有接口：`/api/projects`、`/api/runs`、`/api/inspect`、`/api/creation/jobs`、`/api/media`、`/api/evidence`。
- 交互：
  - 三个工作区标签；剪辑和发布暂时显示占位，并链接到旧创作页。
  - 素材箱和检查器可以隐藏，偏好记在本机。
  - 点时间轴片段会跳转播放，并显示片段描述和采样帧。
  - 快捷键：空格、←/→、J/L。
  - 新请求会中止旧请求，防止串台。
- 保护：`tests/test_studio_shell.py`，覆盖三点：前端库哈希与清单一致，页面没有内联脚本，7 个路由以正确类型返回。

## 第 2 步结果

- 剪辑区（`studio/edit.js`）的布局：
  - 左侧：需求表单。只需填录像、游戏、类型、秒数、平台；其余收在“高级选项”。草稿按项目保存在本机。
  - 左侧下方：方案卡。每张卡显示时长、镜头数、平均镜头长度和前 8 个镜头的缩略图；推荐模板有标记，有缺口的方案不能选。
  - 中间：预览窗，下面是“方案时间轴”，按成片顺序排列镜头缩略图。
  - 右侧：检查器，显示方案信息、选中镜头的原片位置和描述，以及导出设置。
- 即时预览（`studio/preview.js`）：按方案的剪辑清单在原片里跳着播放，同一来源相邻的片段连续播放、不重新定位，输出时钟独立计算；完全不需要渲染。同时用动画帧和视频的 `timeupdate` 驱动，窗口在后台时也能跨片段。
- 导出：沿用原有接口；同一意图复用同一个 `requestId`；完成后预览窗切到成片，提供下载。刷新后会自动重新打开上次的方案或成片。
- 素材箱“我的作品”里的方案和成片可以点击，会在剪辑区打开。
- 实测（demo-phase0，漫画群星，玩法展示 60 秒）：方案生成 1.9 秒；预览从开场镜头（原片 84 秒处）跳回原片开头并连续推进；导出得到 60.0 秒的 MP4（47.2 MB）；页面没有滚动条。
- 保护：`tests/test_studio_edit_browser.py` 使用真实服务器和真实任务系统（只替换了规划器和渲染器），走完“需求 → 方案 → 有缺口的方案不能选 → 导出 → 可下载 → 刷新后草稿和成片还在”。
