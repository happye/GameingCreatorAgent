# 工作台“画面文字”卡片（frame-text-panel，2026-10-27第五会话）

所属阶段：Phase 0（总方案§15本地OCR、§18–21时间线片段的OCR字段；看板A组“OCR”仍为🟡）。单Agent里程碑（Claude Code主控实现，独立评估见第五节）。

选题理由：Phase 0真实验收卡在用户的素材分组决定（不催）。已交付的`ocr-frames`只能在命令行出JSON报告，sprint-ocr-frames第四节明确“工作台暂无OCR面板”。把它放进工作台后，用户在看录像时可以一键读出画面上的字（Boss名、字幕、菜单、片头片尾），点文字直接跳到那一刻，或输入文字找出现的位置。不花钱、不下载、不改变分析／检索排名／验收，是现有能力的使用面补齐，不提前进入后续阶段。

## 一、合同（完成标准）

1. 工作台健康检查在Windows上多报`frame-text-v1`能力；左侧新增“画面文字（本机识别，不花钱）”卡片，选中分析结果后可点“识别画面文字”。
2. 识别只在点击时发生：本机用原分辨率重取任务保存的取帧时刻（复用`build_run_ocr_report`，帧身份与原片哈希核对规则不变），默认“快速”约每2秒一帧，可选“完整”（每个取帧）。同一任务同时只允许一次识别。
3. 结果缓存在仓库`.cache/workspace/frame-text/`（不进项目目录、不改数据库）；重新打开工作台时只读缓存，**原片哈希、时长、任务、识别引擎、识别帧时刻**任一与当前不符就视为没有结果，不自动重扫。
4. 卡片显示：识别帧数／有文字帧数／像真实文字帧数，以及反复出现的像真实文字（最多12条，含首末时刻与帧数）；点击跳到首次出现时刻。输入框“在画面文字里找”按包含关系（忽略大小写和空格）列出命中时刻，相邻命中合并成区间，点击跳转。
5. 页面只用`textContent`显示识别文字；返回给页面的只含文字和时刻，不含词框坐标。报告标明`readOnly: true`、`paidRequests: 0`、`humanReviewed: false`，界面写明“未经人工核对，不影响分析与排名”。
6. 非Windows或本机缺少识别语言时给出明确中文原因，不下载、不安装。

## 二、证据要求

- 定向测试：缓存失效（原片哈希／时长／帧时刻／引擎变化）、并发拒绝、请求格式校验、能力开关、页面不渲染HTML；真实工作台浏览器走查一次（长钟馗快速识别）。
- Ruff／格式／mypy通过；完整verify在提交前或会话收尾跑一次。
