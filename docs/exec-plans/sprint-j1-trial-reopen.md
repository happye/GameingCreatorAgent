## 工程验证

Playwright 使用空白浏览器会话打开指定版本，核对两个复制按钮写入的链接，并在成片列表晚于发布区加载的情况下恢复指定 B 站包。预览视频元数据为约 60 秒，下载名为 `package.zip`，包含视频、封面、标题、简介、标签、平台配置和本地检查结果共七个文件，ZIP SHA-256 为 `66b9e218bedfa257e3a67549edc7a94772a093e715956ba5aa86ceac924dd`。

跨项目或已失效的任务链接停留在素材页并提示原因。加载期间手动切换项目，迟到的响应不会切回原项目。浏览器验证只发出 GET 请求。主验证记录在 `.cache/scratch/narration-captions-20261120/reopen-studio.log`。

## 第六次人工结果

用户确认样片逻辑正确、可直接发布，并判定 J1 通过。前 1 秒无铺垫的打斗是小瑕疵，暂不优先重剪。此次查看现有产物，未计时，也未要求重新从录像生成。用户反馈浏览器用通用 ZIP 名且下载失败，重新生成也一样。希望看到带视频名、平台和类型的文件名，并直接找到本机生成位置。用户还建议说明同一作品的两个版本差异，后续轮换不同游戏。第五次未通过的结果保存在 Git 历史。

## 两个版本和本机交付

两个版本用于验证同一份 60 秒方案的旁白和字幕。初版成片 `a440b9b8995945029fbcbeb41a8c4bf4` 验证本机旁白，新版 `fed21c0e8c9a48d4a770047fcc41dc21` 沿用同一画面编排，将旁白后移 2.5 秒并烧入四句字幕。每次剪辑另存、渲染、保存封面文案、生成平台包都会沿父任务留下记录，因此工作台能在同一作品下找回两条交付链。发布优先选新版 `49799e7b3c8148eeb8b5acfb7337a8ac`，两版画面编排相同，用户可按是否需要内嵌字幕选择。

生成平台包后，工作台显示本机缓存中的原 ZIP。点击「保存到本机导出目录」会将同一份 ZIP 放入素材项目的 `exports` 文件夹，页面显示完整文件位置和复制目录按钮。文件名包含发布标题、平台、视频类型和版本标识。浏览器下载作为补充入口，使用同一个名称。重复保存同一包复用已有文件，内容不同的同名文件会保留。

实测使用《漫画群星大集结》玩法展示和《代号 Atom》高光的既有 B 站包。两份本机 ZIP 和 Chromium 下载均匹配已有 SHA-256，ZIP 内七个条目可读。本次验证的是两个游戏的出包交付，其他游戏的完整 J1 人评仍未做。用户原环境的下载失败未复现。
