# Sprint：J1 可用（创作页重做）

触发：2026-11-02 用户试看 J1“玩法展示成片”，评价**不能用**（`journeys.json` J1 human_check）。
目标：用户第一次打开，10 分钟内不看说明就能从一段已分析录像做出一条约 60 秒成片；然后再次人评 J1。
冻结：P038、P046–P051 继续冻结。本 sprint 只做创作页可用性和方案质量，不扩新功能。

## 用户问到的功能说明

- **活动规则解析**：在本机按固定句式抽取（如“视频时长不少于 30 秒”“带话题 #xx#”），截图和 PDF 先用 Windows 自带 OCR 转成文字。不调用模型；没覆盖到的写法会显示“未识别”（TD020）。结果只是建议，要点“填入需求”才会生效。
- **排除项**：生成方案时，丢掉描述或标签里含这些词的片段，例如填“加载,菜单”，就会去掉加载画面。功能有用，但应移到“高级选项”。
- **游戏知识**：需要自己先添加条目，或导入一个文件夹；不会用 AI 生成。目前只在“解说草稿”里被引用，不参与选片。对首个可用版本来说属于非必要功能，应从主流程移走。

## 计划（按顺序，每步都可单独验收）

1. **向导式主流程**：
   - 拆成 4 步：选素材 → 选类型和时长 → 选方案 → 成片；一次只显示一步。
   - 默认只有 3 个必填项：录像、内容类型、秒数。其余（受众、语气、主题、排除、帧率、活动规则）收进“高级选项”。
   - 游戏知识、套餐、团队、创作反馈移出主流程，放到“更多”页。
2. **方案卡摘要化**：每张卡只显示结构名、镜头数、实际时长、前 3 个镜头缩略描述和醒目的“选这个”按钮，完整镜头列表按需展开。选中后自动跳到下一步。
3. **方案质量**：
   - 通用结构不再“全塞进去”，按目标时长和每镜头 2–4 秒选取片段。
   - 玩法展示模板要达到目标时长的 ±10%。
   - 每个方案标出与其他方案的区别。
4. **按钮状态说明**：灰按钮旁写明“先选择方案”之类的原因。
5. **成片区与历史**：
   - 历史默认只显示“视频”，可切换到其他类型。
   - 点击后在原位置展开，不替换方案区。
   - 提供“清除测试记录”。
6. **草稿自动保存**：每次修改都写入本机，刷新或关机后自动恢复，并提供“清空草稿”。
7. **修正文档**：修正入口名称和手册步骤。手册拆成 1 页“10 分钟上手”，其余作为参考。

验收：
- 浏览器端到端：新用户只填 3 项、点 4 次，就能拿到 MP4。
- 页面高度在一屏半以内（不含展开的镜头列表）。
- 刷新后表单恢复。
- 方案时长误差不超过 10%，平均每镜头不短于 1.5 秒。
- 完成后请用户再试一次 J1。

## 结果（2026-11-02，第一轮改版）

| 计划 | 状态 | 实际做法与数字 |
| --- | --- | --- |
| 1 向导式主流程 | 已做（有调整） | 未做成“一次只显示一步”，因为 12 个浏览器测试和编辑流程都依赖同页元素。实际做法：同一页加顶部步骤条（自动高亮当前步），必填项只剩录像、游戏、类型、秒数、平台；其余收进“高级选项”；活动规则收进“按活动规则自动填写”；游戏知识、套餐、团队、反馈收进“更多工具” |
| 2 方案卡摘要化 | 已做 | 每张卡约 550–750 像素（原约 7,700）；“选择此方案”移到卡片顶部；选中后自动滚到编辑区；镜头超过 12 个时，镜头列表默认折叠 |
| 3 方案质量 | 已做 | 每段画面严格限定在自己的事件内，相邻事件拼接成 2–4 秒的连续镜头；方案时长 58–60 秒/60 秒；平均每镜头 1.7–3.5 秒；渲染校验没有放宽 |
| 4 按钮状态说明 | 已做 | 灰色按钮旁说明原因（先选方案／有未保存修改／转场问题） |
| 5 历史 | 部分 | 移到右侧“我的作品”，按类型分组、视频在前、每组先显示 8 条，可按类型筛选；点击后跳到对应区域。**未做“清除测试记录”**：删除任务会碰到“不删用户作品”的保护规则，需要你决定 |
| 6 草稿自动保存 | 已做 | 改动即保存到本机；刷新后恢复项目、录像勾选和全部字段；可“清空草稿” |
