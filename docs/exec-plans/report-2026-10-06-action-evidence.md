# 本轮汇报：筛片时能先看动作依据

2026-10-06。继续沿Phase 0改善已有录像的查找和核对，没有启动新的付费分析。

现在搜索后打开“检索诊断 · 前十位”，每个候选除了描述和回看按钮，还会告诉你实际引用了几张登记画面、来自几个时刻、覆盖多久。只有一张画面时，会提示这份记录不能确认动作过程；多张画面则提醒回看主体和镜头变化。下载也保留同样的来源时刻和图片摘要，仍不填写人工评分。

这样能避免把“分析窗口曾经发过多张图”误当成“这条动作真的有多帧依据”。本轮核对中，Atom PV旧分析的前十条移动候选，每条都只引用一张图；漫画旧分析的前十条战斗候选也一样。它们的文字可能写成正在移动或战斗，但这一张登记图片本身没有动作过程可对照。候选和原记录继续保留，可回看原片判断。

新版Atom的首条移动候选，实际有四张登记画面，覆盖21–22.5秒，也就是1.5秒。页面已经能显示这个差别。不过，多图仍不代表动作或身份正确：我们看过的38、38.5、39秒画面包含过渡、室内咖啡厅和室外街道，不能只凭图片数量把它们称为同一个连续动作。

另两组注册画面也已由Agent查看：23–25秒可见球体和平台变化，但不能据此认定球体一定由玩家控制；漫画86–88秒可见蓝色光束与数字变化，也不能直接等同枪械射击。这些是本轮排查依据，没有新增独立人工评分。当前资料尚不足以确认“移动候选都是镜头移动”，因此没有加入猜测主语的过滤规则。

诊断还分清相同时刻的多图、不同时间但文件内容相同、仅有音频、登记资料不完整。计数来自候选自己的引用；重复引用不会增加数量，外媒体、错误时钟或缺失资料不会被包装成有效的部分依据。单图提示不否定外观描述，多个不同文件也不会被标成动作已确认。

验证覆盖20个新行为反例以及现有HTTP和浏览器流程，50项定向检查通过。整项目1882项通过、1项因Windows文件链接权限跳过，格式、类型、命令入口和两次一致的离线安装包构建通过；包内71个项目文件同源码，无录像、数据库或缓存。完整检查一次通过，日志及详细测试报告已保存。
