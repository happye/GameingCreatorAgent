# 检索验收素材与查询冻结交付

现在可以先把验收录像、原录制会话、开发／测试分区、查询和人工参考保存下来，再分析或查看模型结果。工具核对本地录像身份和时长，把原输入、冻结时间及缺口保存在新目录；后来绑定同项目已完成分析，便生成现有评测工具可读取的清单。这样不用手工复制录像身份，也能保留“这些问题和参考是在看结果前确定的”那份依据。

同一录制组、相同视频内容或同一查询族跨开发与测试区时，会显示缺口；未知同源关系、代表录像不足、测试已看结果或缺人工参考也不会变成独立ready。草稿能保存，但生成的候选评分始终为空。正式评测新增冻结绑定核对，只允许后来填候选评分和复核状态；如果换了查询、人工参考区间、来源或独立性声明，会拒绝沿用原冻结评测。

实际用本机三段开发录像完成了冻结、绑定和另一进程读回：冻结约1.5秒，绑定约0.5秒；公开PowerShell入口的绑定约1.2秒，生成内容与直接CLI相同。832个项目文件和3个原视频字节保持，0次模型请求、普通搜索、新费用预留或人工评分。两段Atom继续登记为可能同源，整包明确是已看过结果的开发资料，只有两个保守录制组，不算独立验收。程序列明代表素材、独立主查询和人评缺口，没有生成通过结论。

这是验收工具流程的交付，真实独立录像、人工参考和候选可用性仍需要人判断。工具不能鉴定填写人所说的录制独立性；资料ready也不表示70%检索门槛通过。当前不需要你立即补齐资料。下一项主线是候选人工判分入口：固定前十位置、直接回看原区间、填写0–3与独立事件，再生成同冻结依据绑定的评测文件，减少正式验收时的手工整理。
