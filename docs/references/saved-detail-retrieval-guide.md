# 用已有画面细节找片段

在“选择多段录像”明确选好已完成的分析，选择左侧精分析版本，然后勾选搜索区“含已有细节”，再搜索。例如搜“白色头发”，系统会把这个准确版本已保存的、带画面支持的白发观察用于排序。候选展开“已有细节”可以看主体分组、观察及支持画面数量；下载保留镜头、人物和部件身份，点击原候选区间回看自己的录像。

这一选项不会补做精分析。没有准确已保存结果的事件仍用原基础描述；页面显示覆盖数，例如“1/227 个事件有可检索细节”。它不把不确定项、无支持项、自由描述或同部件同时互斥的观察用于正向文字。v4仅使用已验证的人物及持有关系投影，物品不能直接冒充人物。

文字相关性可能来自不同人物。要判断同一个人物是否同时“白发＋持杖”，仍点“核对候选条件”，看全部满足／部分满足／尚未验证／有证据不符。这两种依据分别显示，搜索命中不代表复合条件全部满足，也不代表人工质量验收通过。

新关键词／语义／混合搜索把原描述、同镜头每个人物的已有细节与环境分别计算，各分量取该片段最高分。例如白发属于左侧、红外套属于中间人物时，两个主体的补充词不再合并累计。一个片段仍只返回一次，人物多不获得额外RRF票数；展开“已有细节”能看到关键词和语义各自采用的组，两者可能不同。缺准确细节的片段仍用原描述，不自动补分析。分组改变BM25语料分布，跨版本原分数不能当准确率比较。

下载原联合排名会同时保存原事件事实、时间、证据，以及细节版本、全范围快照、逐候选细节依据。换精分析版本后，旧结果仍明确标原版本，旧条件核对清除；如要按新版本搜索，需要再次明确搜索。后续核对会复核原排名使用的细节快照，细节已改变时拒绝给旧排名贴新结论。关闭选项保留原默认搜索行为，已有历史排名不改写。

命令行和公开脚本使用同一能力：

```powershell
./scripts/search-project.ps1 -Project artifacts/demo-phase0 -Run 96b5f01530ce43e2944828fb0520b9b4,c6d93b984f374cd4aa755ed0c81e4d73,f76f5d6495314c04ae04083614d4afd6 -Query "白色头发" -Mode lexical -DetailProfile v2 -Json
```

Python CLI用`search-project ... --detail-profile v2`；不传此参数保持原基础语料。准确精分析版本为v1–v4，不支持latest或自动借其他基础版本。新文字投影为saved-detail-text-v3，与精分析版本不是同一字段，不会把旧模型结果变成部件版v3；旧文字v1／v2排名仍按原表示精确核对。最多100个不同来源、20,000视觉事件／人物环境组，细节语料及原保存记录最多8MiB；超限明确报错，不截断并称完成。

联合搜索只读原SQLite，新增独立result／receipt两个排名文件。本地语义／混合模式使用已有E5模型，会消耗本机资源；词法不需embedding。没有模型分析、上传、费用预留或真人标签。正式独立人工评测见[人工待办](../exec-plans/human-inputs.md)；日常找片段不用填写验收表。
