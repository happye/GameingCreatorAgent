# 长录像接续与窗口拒绝

长录像的一组画面若返回不合格动作（例如起止都选同一张图），新策略可以保留该组的拒绝记录和费用，继续处理后面画面。它不放松多帧动作证据、不接纳被拒事件，也不重复发送已经成功或明确拒绝的付费窗口。

默认分析仍遇失败停止。已保存的schemaVersion 2任务可在有具体发送／费用授权后显式使用：

```powershell
./.venv/Scripts/python.exe -B -m gamingcreator analyze <原片路径> --project <原项目> --resume <原run> --window-failure-policy isolate-schema-v1
```

策略与原run、来源、配置和pipeline的哈希关联，单事务保存完整标记；它不改原配置／提示词／媒体。后续接续须再次显式选择相同策略，不能与`--retry-uncertain`混用。当前长钟馗的具体方案及一次启动器在`artifacts/long-analysis-reliability-20261011/`，获得新方案的明确费用及图片发送批准后由负责人执行；不要重跑旧试验启动器。

只有账本证明调用已经结束、请求／模型／提示词／图片对应原窗口、费用已知，且拒绝原因属于允许的内容结构错误，才会隔离整组。预算、认证、存储、来源／调用身份、未知费用或未提交成功结果仍停止。新成功响应和恢复时的旧成功窗口同样检查费用与身份，不能仅凭模型说“成功”就继续发送。

每次处理后，任务目录中的`analysis_coverage.json`记录全部预期窗口。`completed`是已保存成功窗口，`rejected`是已核实并保留的拒绝窗口；未完成项另外保留是否尝试、检查点状态及停止原因，避免把尝试失败误称没有调用。范围沿原片时钟，重叠窗口不代表互不相交的视频片段。

有任何拒绝或未完成范围，任务不能成为Completed；处理完后仍可能返回`analysis.coverage_gap`和非零退出码。这时后面的结果已经保存，缺口也明确保存，不能拿来绑定正式验收或完成版检索。重复接续不会自动补发拒绝窗口；补缺口须另行设计具体方案及授权。已有部分事件可沿原本地检查功能查看，不能代替完整覆盖或真人质量判断。

新结构拒绝保留有界安全边界投影、响应SHA与大小，便于离线核对同帧原因；不保存原始返回或任意正文。程序检查证明调度／费用／恢复保护，不证明模型理解准确；Phase 0的F006／F009／F010人工验收仍独立待完成。实现合同及证据见[当前sprint](../exec-plans/sprint-long-analysis-reliability.md)。
