# 搜索候选的条件依据

多录像搜索完成后，点结果区“核对候选条件”，明确选择精分析版本和条件，例如同一个人物“白发＋持杖”，再点“核对已保存结果”。关闭窗口后，每个原候选旁会显示全部满足、部分满足、尚未验证或有证据不符；展开可看当前条件、同一主体的支持／不确定／缺失项目和支持画面数量。点候选原有的区间按钮回看对应录像及原始证据。

这项操作只核对这次搜索已经返回的候选，保留全部候选、原顺序、分数和查询耗时。它不会重新搜索，也不会把没有资料的候选删掉；只来自语音的候选没有视觉主体，会保持尚未验证。若想核对所选录像的全部已有事件，使用搜索区另一入口“核对复合条件”，见[全部事件指南](project-detail-query-guide.md)。

“下载原候选及条件依据”保存原搜索、条件、版本和逐候选依据；原搜索下载仍可单独使用。换查询、模式、候选数量、项目、精分析版本或编辑条件会清掉旧核对，避免把旧结论贴到新结果。只切录像回看会保留当前排名及核对。

基础分析和精分析都要求准确版本。同一录像的不同基础版本不能借用彼此结果；尚未验证不代表原片没有该人物或动作。原基础描述的‘白色头发’词法查询返回34候选且全部未验证，35–36秒已有partial事件未进入排名；2026-10-08已交付可选[已有细节检索](saved-detail-retrieval-guide.md)，该事件在一次真实对照中进入新前十第5位，核对仍partial。两种搜索保持原排名记录，各自的核对不补回当前排名遗漏；程序检查不等于内容质量通过。

命令行使用同一只读能力：

```powershell
./.venv/Scripts/python.exe -B -m gamingcreator match-search-details --project artifacts/demo-phase0 --search <原searchId> --search-sha256 <原搜索内容摘要> --input detail-query.example.json --profile v2
```

`searchSha256`由联合搜索HTTP响应提供，或用Application的`search_snapshot_sha256`计算原保存文档的规范摘要（排除响应的project和searchSha256）；它不同于保存回执中原文件字节的SHA，两者分别复核。不能传客户端候选清单或任意文件路径，原搜索缺失、修改或与Completed素材／区间／证据不符会拒绝。最多100来源、100候选和8MiB响应，超过明确报错。

操作读取已有结果，不启动模型、不上传画面、不预留费用或写搜索／数据库。正式检索质量仍须独立人工参考和评分，日常使用不必填验收表；人工协助时点见[人工待办](../exec-plans/human-inputs.md)。
