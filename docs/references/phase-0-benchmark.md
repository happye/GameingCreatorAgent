# Phase 0 评测合同 v1

源要求：总方案 §45–46、59、71 的 Top10 ≥70%。本文件补齐可重复计量口径，不降低门槛。

## 数据集与人工标签

最终准备 10–20 段代表性游戏录像，按原录制会话拆分开发与冻结测试集。同一 PV、其剪辑/实机版本或同源切片不得跨集；查询改写归同一族。先确定录像、查询、事件、区间、分组和 reviewer/labelVersion，再看模型结果；失败后用于调参的测试集必须重新标记并更换独立验证集。

当前四段本地开发素材合计490.693314秒：两段PV、一段名为“实机”的剪辑和额外275.831秒Atom录制。其中Atom的PV/剪辑可能同源，先视为同组；不能当小时级或10–20独立会话最终benchmark。从文件命名不能证明完整实机分布。

人工观看原时间码片段评分：0 无关；1 相关但不可用；2 可用；3 高度相关。仅 2/3 计入有用。记录独立事件 ID、理由、可用区间与标签版本；模型摘要、打分或 self-review 不能代替人评。单 reviewer 与未复核标签要在报告披露。

## 查询分组与固定分母

- 主组：清晰机制查询，预先人工确认素材库有至少 10 个独立可用事件。
- 少例组：有 1–9 个可用事件；单独报告事件 Recall@10 与返回片段精度，不用不可能达到的 7/10 强行评价。
- 负例组：无可用事件；报告错误推荐/拒答及错误证据，不混入主组平均。负例告警阈值需在最终 benchmark 前登记，目前尚未锁定。

`U10 = 前十个位置内人工评级 2/3 的独立事件数 / 10`。少返回的槽位计零；同一事件重复片段计零，即使片段不重叠。按排序后的前十槽计算，不从第十一条及以后补位。逐主组查询要求 ≥0.70，同时报告宏均值、最低分和每机制分布。其他查询完整展示，不能跑完后再挑入主组。

时间指标：候选区间与人工可用区间的起/止误差，中位数/P90、越界次数；另报事件召回/漏检、重复率、人工筛选时间。没有标注则这些值是 null，不输出虚构百分比。

## 成本与速度

冷启动每源小时 API 成本按全部 attempt 计入，包括重试、超时和取消；热缓存另报。缺官方价格版本、usage、计费单位、币种汇率或失败计费证据时 cost unverified、cost gate null，未知不写零。价格完整可估算 estimated，账单核对 confirmed。§51 建议 `<¥5/h`（优化 `<¥2/h`）使用冷启动全量素材分母。

记录总墙钟时间/素材时长实时比、CPU/GPU 配置、峰值资源和可测 GPU 秒。累计请求耗时不等于墙钟耗时。原方案没有硬速度阈值，本轮先测量；后续锁用户等待时间。整条创作主动时间节省 >60% 属后续发布包阶段。

## 可运行的计分回归

`scripts/score-retrieval.ps1 -InputPath <json>` 接受 `schemaVersion:1, evidenceType, datasetId, queries`。每个 query 有 `id, kind(main/sparse/negative), referenceEventIds, hits`；hits 数组必须已按最终 rank 排列，各项有 `eventId, grade(0..3)`，必须已判分。脚本直接取数组前十项，不读取或重排 rank 字段。评级 2/3 的事件必须属于 referenceEventIds；主组至少十个独立参考事件，标签不能重复。

`scripts/test-retrieval-score.ps1` 合成验证：7/10 通过、1 个结果只能 10%、重复事件不灌水、负例返回报警；未判分、布尔值、字符串、小数和越界评级拒绝。工具只计算指标，不证明标注真实性、独立测试集或 Phase 0 已通过。合成用例与 API 图像请求成功均不能当质量 gate。
