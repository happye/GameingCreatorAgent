# 用表单登记录像和事前查询

这一步用于分析或查看模型结果前，确定验收录像、同源关系、用途和要找的玩法。可以先保存没填完的登记草稿，继续填写后导出已有流程接受的计划文件，不必手写来源／查询JSON。这里不读取录像内容、模型输出或分析项目，不分析、搜索、上传或预留费用。

## 打开登记页

在仓库根目录，使用已准备好的PowerShell 7：

```powershell
./scripts/prepare-benchmark-plan.ps1 -OutputDirectory artifacts/plan-editor-001
```

打开生成的`artifacts/plan-editor-001/edit.html`。初始没有录像和查询，未知声明不会被填成“独立”或“没有看过结果”。它是单独的本机文件页，不在8765工作台菜单中，不需要另起服务。

已下载登记草稿，或已有尚未包含人工参考／版本／填写人／复核的旧计划，可以用它生成继续填写的页面：

```powershell
./scripts/prepare-benchmark-plan.ps1 -InputPath artifacts/registration-draft.json -OutputDirectory artifacts/plan-editor-002
```

页面里的“继续登记草稿”只载入本页保存的草稿；旧计划用上述公开入口载入。旧输入的相对录像路径以输入文件所在目录为起点，生成时转为绝对路径；这不代表文件已核验可读。已有人工参考的计划会拒绝登记导入，应回[原片标注页](./benchmark-reference-review-guide.md)继续，避免改来源或查询时悄悄丢掉判断。

## 填写和保存

先填本次计划名称，再增加录像和查询。

| 登记项 | 填写方式 |
| --- | --- |
| 录像编号 | 每段不同，查询据此关联；修改编号会同步已有查询的关联 |
| 完整本地路径 | 例如`G:\录像\原片.mp4`，不要包含外层引号；正式导出前须填写完整路径 |
| 来自哪次录制 | 同一录制的PV、剪辑或版本保持同组，未知先留空；名称或文件数量不能证明独立 |
| 用途 | 明确选择开发／调试或独立测试，同录制组不得跨用途 |
| 是否看过模型结果 | 如实选择；不知道保留“尚未确认”，可以保存草稿，但暂不能导出计划 |
| 查询编号与想找什么 | 每查询不同编号，填写清晰的实际机制需求；例如寻找闪避后反击 |
| 同一需求／改写归组 | 同需求及改写保持同组，不把改写跨开发／测试分区 |
| 查询类别 | 主查询须事前有至少十个独立可用参考；少例1–9个，负例无可用事件 |
| 对应录像 | 明确选择该查询核对的原录像 |

没有填完就点“保存登记草稿”，保留下载的`验收登记草稿.json`。它记录未知项，不是有效验收计划；关闭前下载，页面不会自动保存。下次在同一页载入，或通过公开入口生成新的继续页。

删除有查询关联的录像会提示先删除或调整对应查询。重复编号、缺少用途／是否看过结果／对应来源等须填写后才能导出；草稿可保留这些未完成内容。错文件、重复JSON字段或载入期间的新编辑不会覆盖当前登记。

## 接到原片标注与冻结

填齐后点击“导出待核对计划”，下载`事前验收计划.json`，把它放在本地，例如`artifacts/acceptance-plan.json`。登记页不探测文件或认证独立性，导出只检查登记格式。随后：

```powershell
./scripts/prepare-benchmark-references.ps1 -InputPath artifacts/acceptance-plan.json -OutputDirectory artifacts/reference-review-001
```

原片入口才会核对实际录像身份和时长。接着看原片、登记真实动作区间、保存／导入参考，再通过[验收准备指南](./benchmark-preparation-guide.md)冻结、绑定和评测。生成的计划人工参考始终空、确认false、标签版本null；没有代填人工判断，也不会自动冻结或启动模型。

每次输出使用新目录，保留旧输入和页面包；已有目录或与原输入／登记来源重叠时拒绝写入。中断目录不是完整生成结果，不删除原资料覆盖重做。

实际三段开发录像的原计划已验证桌面／窄屏登记、声明保持、未知值阻断、下载载入、公开草稿继续及原片标注衔接。它们仍是开发资料，准备工具通过不能代替F006独立人评；各主查询固定十位至少70%有用的门槛保持。
