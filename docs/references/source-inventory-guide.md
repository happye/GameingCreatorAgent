# 素材来源盘点：找出画面相同的录像

登记验收分组前，先用这个本机命令检查素材是否有“字节不同、画面相同”的情况，例如宣传片剪入了实机镜头。它给出具体证据，帮你决定哪些录像应归同一原录制会话；它不分析、不调用付费模型、不写入素材目录，也不会替你分组。

## 使用

在仓库根目录：

```powershell
./scripts/inventory-sources.ps1 -InputPath GameVideos -OutputPath artifacts/source-inventory.json
```

`-InputPath`可给多个文件或目录；目录会递归查找`.mp4`并固定排序。输出文件必须放在素材所在目录之外，先写临时文件再原子替换。也可直接运行`python -m gamingcreator inventory-sources --input <路径...> --output <json>`。

## 报告内容（`source-inventory-v1`）

- 每个来源：路径、字节数、SHA256、来自流时钟的时长（微秒）、视频编码／尺寸／帧率、采样帧数和有信息量的帧数。
- `duplicateGroups`：SHA256完全相同的副本。
- `sharedFootageCandidates`：两个不同文件之间疑似共用画面的证据：偏移秒（A时间减B时间）、相近票数／可比票数（`matchedVotes`／`comparedVotes`，相邻±1偏移上的相关投票，不是帧数）、A方不同相近采样数（`matchedFramesA`）、该对的背景相近率、校正后概率、`clusterCount`，以及最密集连续一段（相近采样间隔不超过4个采样，即2秒）的A／B首末时间，远处的偶然命中不会拉长范围。时间是2帧／秒采样序号换算的近似秒，不是逐帧精度。
- `notComparable`：有效画面不足20个采样的来源（如全黑画面只有声音），不参与比较，不能据此判断是否独立。
- `failedSources`：探测或解码失败的文件（编号、路径、错误码、说明），其余素材照常比较；只要报告写出，命令就返回0，请看控制台清单。
- `parameters`、`ffmpegVersion`、`limitations`；`humanDecisionRequired`恒为true，不含任何`recordingGroup`建议。

## 怎么判断

每个文件按2帧／秒缩成9x8灰度图并生成64位差值哈希；低对比度帧（如纯黑、纯色）不参与。同一偏移上汉明距离不超过10的帧算相近，相邻±1采样偏移合并投票，再对比该对文件整体的偶然相近率，做二项检验并按偏移数校正（Bonferroni），校正后概率不超过1e-6且至少20个可比采样才报告。票数彼此相关，概率只是名义排序分数，不是精确概率。采样方式、哈希、阈值均取自实际使用的提取器与参数。例如“PV与实机”在某个固定偏移上约四分之一的帧相近，而其他偏移不到7%，就会被列出。

## 限制

- 命中只说明有共用画面的证据，仍需人工看视频确认；未命中不证明独立。
- 静态标题／logo卡（黑底白字、白底logo等）会被排除：相近帧里至少要有3个互不相似（汉明距离不小于6）的画面，且A、B两侧都要满足；因此动作很少的极短共用镜头可能漏检。同一对文件里与更显著结果覆盖同一段画面的候选只保留一个。
- 裁切、黑边、镜像、大面积叠字、变速可能漏检；画面长期近乎相同的素材（固定界面、重复标题）区分度低，可能不报告。
- 报告不改变冻结计划，也不自动分配录制组；是否同组由人工在登记时决定。
