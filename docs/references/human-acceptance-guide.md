# F006 人工检索验收

F006评估查询结果的内容质量。UI审美、布局、响应和选片操作另按工作台验收，不互相替代。完整计量合同见[phase-0-benchmark.md](./phase-0-benchmark.md)，输入格式见[benchmark-manifest-schema.md](./benchmark-manifest-schema.md)。

## 怎么判分

人工观看候选的实际源视频区间，核对查询、关键动作/结果、起止和上下文，记录理由：

| 评分 | 含义 | 判断提示 |
| --- | --- | --- |
| 0 | 无关 | 没出现所查询的内容，或证据指向错误 |
| 1 | 相关但不可用 | 有相关线索，但关键内容不清楚、缺动作/结果或上下文，需要大幅重新找片 |
| 2 | 可用 | 当前区间足以作为该查询的说明素材，关键内容可辨且边界可接受 |
| 3 | 高度相关 | 内容明确、表达完整，且对该查询很有代表性 |

提示用于统一判断，不擅自规定视频必须多少秒；最终数据集先登记具体业务“可用”规则。模型文字、分数和点击片段篮都不是人工评分。单人标注可以记录，但要披露reviewer及是否复核。

## 什么才算通过

每个主机制查询事先须有至少十个独立可用参考事件。按最终排名前十个固定位置计算：**至少七个不同真实事件获2/3，即U10≥70%**。不足十条的空位计零；同一动作的重复片段计零，不能拿第十一条补位。每个主查询都须通过，不只看平均值。

仅有1–9个可用事件的查询单独报召回/精度；没有匹配事件的查询单独报误推荐。原视频区间的起止误差、漏检/重复、处理时间及全部尝试的冷/热费用同时记录。未知费用保留null。负例告警、可接受时间误差和硬速度阈值尚未冻结，不能虚构为已经满足。

## 操作顺序

1. 准备10–20段代表录像，按录制会话划分开发与独立测试集；同源PV/剪辑不能分到两边。
2. 在看模型结果前，冻结查询、分组、人工参考事件与可用区间、标签版本及reviewer；调参用过的测试集不能继续充当独立最终验证集。
3. 看每个返回的实际片段，登记精确区间、评分、理由及对应humanEventId；不同模型事件指向同一真实动作仍算重复。
4. 将标注填入模板并运行 `gamingcreator benchmark`。未标注/未冻结/不独立时qualityGate保持null；失败报告也保存，退出6不等于工具没运行。

当前开发PV命中及UI反馈可用于改进，不能代替这次独立内容验收。现有素材不足以宣布最终F006通过。本轮开发不需要你立即补齐标签或阈值；正式评测前再确认数据与上述业务判断口径。
