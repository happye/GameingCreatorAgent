# 原片标注：每个框怎么填，为什么要填

这页是给“找片段”留下正确答案。你先看原录像，记下自己认为符合需求、实际能用的片段；以后把搜索结果拿来对照，判断有没有找对。每找到一段就登记一条，不用写技术术语或逐帧标注。

上半部分管整份记录，下面的视频和片段框管当前选择的录像／需求。当前三录像各四需求，共十二项；填写一部分也能保存，两个确认框不要急着勾。

| 上方字段 | 怎么填 | 为什么要填 |
| --- | --- | --- |
| 人工参考版本 | 这份答案的名字，例如“原片标注-v1”。可先留空保存草稿，准备正式确认时填写；以后修订可用v2 | 区分先后两份人工答案，防止以后对照时用错。不是AI版本，每加一个片段也不用改一次版本 |
| 填写人（每行一人） | 填实际标注者的名字或昵称，你一个人填就一行；可先留空保存草稿，正式确认时必须填 | 说明是谁亲自看原片给出的答案，不填AI或没有参与的人 |
| 人工参考已实际确认 | 这整份记录准备交付、各项都核对清楚时才勾。只标了一部分先不勾 | 声明真人确认过这份答案，适用于整份记录，不只是当前下拉选中的查询；下载草稿不用勾 |
| 人工参考已由人复核 | 标完后实际回看原片、核对区间和重复归组，再按实际复核情况勾；尚未复核先不勾 | 区分初次填写和后来核对。AI检查不能充当真人复核；只有一名标注者的情况会如实披露，不虚构第二个人 |

| 片段字段 | 怎么填 | 为什么要填 |
| --- | --- | --- |
| 选择事前查询 | 选“想找什么＋哪段录像”，例如“找释放连招的画面·钟馗15分钟录像” | 每条答案要归到正确需求和原片；同一录像不同需求分别登记 |
| 可用起点（源时间秒） | 标素材从哪里开始，推荐暂停到合适位置后点“用当前位置标记起点” | 让以后能回到正确位置，也能检查搜索截得是否合适 |
| 可用终点（源时间秒） | 标素材在哪里结束，暂停后点“用当前位置标记终点”；必须晚于起点 | 说明你认为能用的完整范围，尽量保留看清动作所需的开始和结束 |
| 真实事件名称 | 用你看得懂且能区分这次事件的名字，如“第一套三连击”“第一次打开武器界面” | 记清发生了哪件事，避免一堆答案都只叫“战斗”而分不清 |
| 独立动作归组 | 简单用“连招01”“连招02”。同一次实际动作的几个片段保持同一个归组；后来重新发生的一次动作另起名字 | 防止把一次动作截成十段，就算成十次成功。这里是“同一次事情”的编号，不是动作类别，所有连招不能全填一个“连招” |
| 为什么这个区间可用 | 一句描述看到了什么、为何符合所选需求，例如“起手、连续三次攻击和收招都能看清，可用于连招展示” | 以后知道你判断符合需求的依据，区分真正能用和仅仅相关的画面 |

时间框用总秒数：1分20秒填80，2分05秒填125；也可以填80.5，不写1:20。播放器标记后仍回看核对范围。如果页面提示特殊起始时间、自动标记按钮禁用，先告诉负责人，不直接猜换算。

下面是假设示范，不是对这批原片的实际判断：假设看见1分20秒到1分24秒有一套完整三连击，查询选“找释放连招的画面”及对应录像，起点80，终点84，真实事件名称“第一套三连击”，独立动作归组“连招01”，理由“起手、三次连续攻击及收招都清楚，能作为连招展示”。点击“登记这个可用区间”，下方出现记录才算登记成功。

如果同一次三连击还有另一个可用范围，保持原事件名称和“连招01”，可以继续登记范围。后来出现另一套真正不同的连招，名称改为“第二套三连击”，归组改为“连招02”。同一次boss战或剧情事件切成多个片段也不能凭片段数多算事件。名称区分具体发生了什么，归组防止同一件事被反复计算；最简单的做法是同一事件始终用固定的一套名称和归组。

四类需求按你实际搜素材时的标准判断。武器展示“界面”需看清武器展示页面，单纯战斗时拿着武器通常不算；连招看完整连续动作，单独一道特效通常不够。boss战和剧情演示按原片内容及你掌握的游戏背景判断，拿不准的把疑点说出来，不当确定答案。

“登记这个可用区间”把当前片段加入页面；“保存当前标注记录”才会下载本地文件，页面不自动保存。关闭、刷新或下次继续前先保存。切换查询会保留已登记的记录，但当前尚未登记的框会清空，先登记再切换。下次打开同一个原片页，用“继续已有标注”选择上次下载的记录，再接着填；改完再次保存，用最新文件反馈。

没有对应内容的需求留空，反馈时明确说“哪段录像＋哪个需求没有”，不用造一条不存在的事件。页面“至少十个独立参考”是正式主查询评测的要求，不是要求凑数；少例或没有内容的查询会如实分类，完整验收需要的素材后续补齐。

保存后给负责人最新记录的本地文件位置、完成了哪些录像／需求、哪些需求确实没有内容。也可先保存一小部分供核对，未完成的部分说明即可。负责人会核对原包和记录，再处理冻结与后续新分析授权，下载不自动完成验收。
