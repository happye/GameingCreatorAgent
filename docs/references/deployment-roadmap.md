# 本地、云端与桌面 EXE

本文件解释当前运行方式与原总方案§11/15/62的对应关系，不宣布新部署能力。Phase 0语言采用ADR-001的Python；本地检查界面遵循ADR-002。

## 当前是什么

运行 `./scripts/run-ui.ps1` 后，项目内Python仅在本机 `127.0.0.1` 提供页面和API。浏览器是界面容器，服务与计算仍在你的电脑；这是本地开发工作台，尚未打包成EXE。

| 工作 | 当前执行位置 | 数据边界 |
| --- | --- | --- |
| 视频探测、抽帧、音频提取 | 本机FFmpeg | 原视频保留原位，不默认上传 |
| ASR、E5语义检索、词法排序 | 本机模型/核心 | 权重、证据、向量和缓存在项目内 |
| 时间轴与分析状态 | 本机SQLite | 数据库保存路径、结果和版本，不存完整视频字节 |
| 视觉理解 | DeepSeek远端API | 新分析只发送抽样的证据图片；有网络与费用 |
| 工作台预览/查询/区间导出 | 本地页面与服务 | 读取已有结果，操作不发付费视觉请求 |

因此已有结果可离线浏览/搜索；当前的新视觉分析不是全离线。OCR、Proxy、最终视频渲染等是原方案中的后续能力，不能因在“本地负责”清单里就称已实现。

## 最终 EXE 会改变什么

EXE是启动/分发形式，云端是计算位置，二者并不互斥。原方案目标仍是Windows Desktop EXE、本地处理大视频、必要AI推理调用云端。以后可以将既有本地核心和界面封装为便携桌面应用，统一启动与关闭、文件选择、进度/取消/恢复及升级；底层Python核心无需因打包就重写。

嵌入界面技术、便携打包、许可证与升级测试须另立ADR，保持用户要求的环境隔离。不把现在的浏览器检查页当正式桌面交付，也不因使用HTML/CSS就改成纯Web SaaS。

## 若将处理改为云端

远端服务不能直接读取你的 `G:\` 文件。完整云端方案需要上传或代理媒体、对象存储、账号/项目隔离、鉴权、后台任务队列、计算配额、失败恢复和费用管理；还要明确素材保存期限、下载/同步和删除行为。上传大视频增加带宽与等待时间，服务端算力和存储会产生持续成本。

这会改变存储和任务边界，不是把当前localhost服务改为公网监听。现有Domain/Application/Provider分层可复用业务合同，SQLite、本地路径和任务执行适配则需要按新场景调整。仅界面或项目元数据放云端、媒体仍在本机也是可独立评估的混合路线。

当前按原方案继续本地优先；本轮只改善布局与选片工作流。完整云端托管和正式桌面封装均未开始。
