# 第7步评分页省力辅助（review-page-aids，2026-10-27第五会话）

所属阶段：Phase 0验收第7步（前十名人工评分；看板第3节、human-inputs“固定候选评分”）。选题：第二轮离线候选排名工作流（3视角侦察＋3评委）第一名，7.67/10（安全分最低7）。不改评审记录格式、核对、计分或排名，不代填人工判断，不花钱。属人工标注／验收边界，评估者为code-quality-guard。

## 一、对用户来说多了什么

1. 每个查询的当前填写计数：评为可用的不同独立事件几个、未判定／重复／缺位各几位；**不显示门槛或“还差几个”**（避免影响评分独立性），写明“请只按画面判断，计分以第8步报告为准”。
2. 重复说明：评2/3分的位置若与前面已评为可用的位置是同一独立事件或同一动作归组，中性说明“如果确实是同一个动作，保持即可，第8步按重复处理”；评2/3分未选独立事件也提示。
3. 时间重叠提示：候选与冻结参考区间在时间上重叠时列出参考名与秒数，写明“只是时间重叠，请回看后自己判断，不会自动填写”。
4. 冻结参考区间的“回看参考”按钮，复用已有原片时钟核对的播放。
5. 键盘：`J`／`K`在可评分位置间移动（跳过缺位和已知重复），`P`回看当前位置；评分下拉框保留原生的数字选择，“对应的独立事件”下拉框不响应这些快捷键。

## 二、合同

- 预览计数与`application/benchmark.py`第8步规则一致：前面出现过的同一检索事件、或已算可用的同一动作归组即为重复；只有评2/3、非重复、未越界且对应参考的不同独立事件计入可用。
- 记录格式、`validate()`、下载与载入不变；所有新增只读显示。

## 三、证据

- `tests/test_benchmark_review_aids_browser.py`（真实Chromium，1366与390宽）：初始计数为0且不出现“门槛／还差／已够”；重叠说明点名参考human-3且所有评分仍为空；10个参考回看按钮；按真实填写（含同一独立事件第二次评3分、0/1分、未判定）后，页面计数与把**下载的同一份记录**交给第8步`run_benchmark`的结果一致——可用不同事件3、重复2、未判定3、缺位0；重复说明点名“第1位”且不提“0分”；`K`跳过已知重复位置到第3位、`J`回第1位；事件下拉框中按`k`不跳走；`P`给出播放状态；载入刚下载的记录后计数不变；理由框中按`k`不移动。`test_benchmark_review.py`、`test_benchmark_source_clock_browser.py`、`test_benchmark_workflow_browser.py`等通过（`test_benchmark_source_clock_browser.py`在多个浏览器测试同时跑时有1次播放定位超时，单独连跑3次全部通过，与本改动无关，记为观察）。
- 真实已保存评分页（验收流程331ac451第7步，3个查询、15个候选，无冻结参考）：用新页面重新生成后，计数正确随选分变化（未判定2→0），`K`到第2位、`P`经原片时钟核对播放真实片段11.5–12.5秒，无页面错误。

## 四、独立评估

code-quality-guard（opus）＋两票反驳工作流首轮：**FAIL**，1个P1经两票确认——评分时实时显示“主查询需要至少7个才过门槛，还差N个／已够”，会把边界片段往“可用”推，影响人工判断独立性；且未判定位存在时第8步并不计分，“已够”会误导。已改为只显示中性计数（不提门槛与差额），并写明“请只按画面判断”。P2同批修复：重复说明改为中性（不提扣分），事件下拉框保留原生输入跳转，补充`P`键、载入后计数一致、事件框不被快捷键劫持的测试。复审：code-quality-guard **PASS**，确认P1与各P2已修；其提出的两处测试力度不足（`P`键断言原本恒真、参考回看按钮只计数）已补：`P`后播放状态必须改变并给出原片原因，无时钟时参考回看按钮全部禁用且有原因说明。
