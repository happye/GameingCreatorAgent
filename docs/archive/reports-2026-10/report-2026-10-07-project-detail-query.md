# 多录像条件核对与人工验收说明

现在可以对选定的几段录像统一核对明确条件。例如选择“白发”和“持有杖”，系统检查这些录像的全部已有事件，区分全部满足、部分满足、尚未验证和有证据不符，再让你筛选、翻页、查看依据、回看对应原片和下载当前页。不用逐个点候选，也不会因片段排在搜索前十名之外就漏掉核对。

真实三段开发录像共227事件，约0.8秒得到0个全部满足、1个部分满足、226个尚未验证。现用桌面和窄屏都能翻页、筛选、下载并回看35–36秒原片。缺依据说明旧精分析覆盖不足，不能断言其他画面不存在；不同基础或精分析版本也不能相互借结果。本轮没有新增模型请求、搜索记录、费用或真人标签，原录像、856旧项目文件、217原排名及费用提案保持。

新功能26项检查及相关48项通过；一次整体检查2310通过、2个旧失败、1个Windows权限跳过。两旧失败涉及验收完成状态和批量准备状态，已登记TD014／TD012，不反复定位、不称整体全绿。两个离线安装包一致，独立运行得到同样实际结果。新入口已更新本机工作台，用户原“第一批玩法验收”空资料保持。详细证据见[本轮sprint](sprint-project-detail-query.md)。

你问的“验收流程”不是日常找素材必填表，也无需现在填完八步。它属于开发中的正式人工质量验收：先看原片标出真实动作和区间，再检查AI找出的前十个片段是否可用。比如想找打Boss，就先登记原片真正打Boss的时段，再回看系统结果并判断。准备和关联资料、保存恢复及计分由工具处理；真实内容判断需要人来做。工具完成不等于真实标注已经完成。

目前已提醒并记录的人工需求是：准备代表性独立录像并确认录制分组；**在独立测试素材分析／看结果前**标原片参考；生成固定结果后判断候选是否有用。日常使用及本轮离线开发不等待这些表填完，正式验收需要完成相应人工部分。具体操作入口、触发时点、状态和证据见[人工待办](human-inputs.md)。新付费实验授权仍未答，仅阻断该实验，旧未知费用继续保留。

“需要人工帮助第一时间提醒并记录”“持续同步里程碑和进度”已经写入AGENTS、共享协作协议及Codex／Claude／Grok入口，适用于所有Agent及恢复。HANDOFF、assignments、progress置顶摘要和Phase 0计划均已对齐，旧推送失败保留为历史；上一积压已同步，当前提交／远端发布以Git及publication回执为准。F006/F009/F010保持未通过。
